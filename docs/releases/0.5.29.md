# Inkspan 0.5.29 release evidence

**Release candidate:** 0.5.29  
**Prepared:** 2026-08-05  
**Source baseline:** `main` after PR #62

## Release scope

Inkspan 0.5.29 promotes the durable autosave validator session merged in PR #62. The release adds a framework-independent coordinator that binds each single-flight save to the exact server-issued strong entity tag loaded or last committed by the host.

The release includes:

- RFC 9110 strong entity-tag syntax validation;
- exact sequential `If-Match` validator handoff;
- explicit conflict and ambiguous-failure recovery;
- fail-closed descriptor-based option and callback-result validation;
- detached immutable revision evidence;
- coherent lifecycle and durable-validator snapshots across recovery and shutdown microtask races;
- ESM, CommonJS, and strict TypeScript package-consumer verification without React, TipTap, ProseMirror, or Yjs installed;
- operator documentation and APA 7th doctoring.

## Release acceptance

The source feature merged only after its exact PR head passed:

- TypeScript type checking;
- 100% production statement, branch, function, and line coverage;
- deterministic library and demo builds;
- isolated packed-package ESM, CommonJS, and strict TypeScript consumers;
- Python 3.11 and 3.14 Office tests with 100% branch and docstring coverage;
- Office wheel, schema, and license verification;
- Security Scan;
- SAST Semgrep;
- CodeRabbit status;
- resolved inline review threads.

This release branch must repeat the complete exact-head repository gates after changing version and changelog metadata. Tag creation, registry publication, provenance, and immutable GitHub Release publication are not complete until the release commit itself passes those gates and is merged.

## Ownership boundary

Inkspan owns local ordering, validator syntax, and process-local validator handoff. Hosts continue to own transport, authentication, authorization, tenant isolation, persistence, atomic durable comparison and commit, migration, backup, retention, audit storage, retry and idempotency policy, conflict UX, credentials, and model-use policy.

## Rollback

If release acceptance fails, close the release PR without publishing a tag or registry version. The already merged feature remains under the prior package version until a later release candidate completes the gates.
